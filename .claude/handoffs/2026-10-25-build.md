## Layout

```
claude-config/
  CLAUDE.md                     standing instructions; install links it to ~/.claude/CLAUDE.md
  skills/<name>/SKILL.md        each dir linked to ~/.claude/skills/<name>
  templates/slidev-presentations/   copied by hand into a presentations repo
  install.sh                    symlinks only; refuses to replace anything it didn't create
  test/                         install test
  README.md
```

## Skill rules

- Carry only the payload: rules, procedures and verified facts Claude does not apply unprompted.
  No generic how-to. As short as the payload allows.
- Read `~/.claude/CLAUDE.md` first; a skill never restates it. Where a brief conflicts with it,
  CLAUDE.md wins.
- `description` is the trigger: what the skill does for the user and when to use it, then
  "Not for X" where a neighbour could misfire. No packaging talk.
- A platform fact carries its Claude Code version or a doc URL with the date read. Where briefs
  disagree or a fact is unversioned, check the current docs; drop what you can't confirm.
- No employer names, tools, paths, people or ticket formats anywhere.

## Commits

Plain Conventional Commits, no attribution trailers. One commit per coherent group, small enough
to review. Agents share one repo: stage and commit only your own paths,
`git add -- <paths>` then `git commit -m "<msg>" -- <paths>`; on an `index.lock` error wait and
retry. This handoff lands with the install-script commit. No remote; never push.
