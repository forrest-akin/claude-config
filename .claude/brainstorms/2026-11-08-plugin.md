# Brainstorm: ship claude-config as a Claude Code plugin

Date: 2026-11-08. Seeds the planning phase. Decisions below are Forrest's and final.

## Goal

The repo installs as a plugin with two commands and no script:

```
claude plugin marketplace add forrest-akin/claude-config
claude plugin install claude-config@forrest-akin
```

Skills load as `/claude-config:<skill>` (bare names keep working unless another plugin claims
them); the three hooks register through the plugin; `install.sh` and its test are deleted.

## Decisions

- Plugin name `claude-config`, marketplace name `forrest-akin`.
- `CLAUDE.md` is Forrest's own standing instructions. It stays tracked in this repo but is not a
  plugin component; the existing hand-made `~/.claude/CLAUDE.md` symlink keeps working and README
  says the file is personal and not installed by the plugin.
- Skills and hooks stop depending on CLAUDE.md. Every rule or figure a skill needs is stated in
  the skill. Citations today: `subagent-model-tiering/SKILL.md:3` (description points at CLAUDE.md
  "Subagents" for agent count), `workflow-design/references/platform.md:37` ("CLAUDE.md
  'Subagents' sets the call budgets"), `hooks/bash-prefix.sh:8` (denial message cites
  ~/.claude/CLAUDE.md "Bash commands"). `extension-authoring` mentions of CLAUDE.md are about the
  platform concept, not this file, and stay.
- Migration on this machine is approved: the final installment removes the repo-owned symlinks
  under `~/.claude/skills` and `~/.claude/hooks`, removes the three hook entries from
  `~/.claude/settings.json`, adds the marketplace, installs the plugin, and verifies.

## Facts read from the docs on 2026-11-08

Local copies in the session scratchpad: `plugins-reference.md`, `plugins.md`,
`plugin-marketplaces.md`, `components.md`, `skills.md`, `hooks.md`
(`/private/tmp/claude-502/-Users-forrestakin-github-com-forrest-akin-claude-config/e414a86e-89c9-49e3-babd-0f466854f902/scratchpad/`).

- Manifest at `.claude-plugin/plugin.json`, optional; every other file at the plugin root.
  Standard layout: `skills/`, `hooks/hooks.json`, `agents/`, `commands/`.
- `hooks/hooks.json` wraps the event map in a top-level `"hooks"` key; commands reference scripts
  as `"${CLAUDE_PLUGIN_ROOT}"/hooks/<name>.sh`. `CLAUDE_PLUGIN_ROOT` is exported to hook processes.
- `${CLAUDE_SKILL_DIR}` is substituted in plugin skills (the skill's own directory);
  `${CLAUDE_PLUGIN_ROOT}` also. Neither is in the environment of Bash-tool commands.
- Plugin skills: `/plugin-name:skill-name`; frontmatter `name` sets the last segment; bare
  `/skill-name` also works unless taken. `presentation-narrative` collides with the
  `anthropic-skills` plugin today.
- A `CLAUDE.md` at the plugin root is not loaded; `claude plugin validate` warns about it.
- Marketplace: `.claude-plugin/marketplace.json` at the marketplace root; each entry has `name` and
  `source`; a relative `source` is from the marketplace root; a plugin at the marketplace root is a
  supported case (submodule caveat only). `claude plugin marketplace add <owner>/<repo>` for a
  GitHub repo; `claude plugin install <name>@<marketplace>`; `claude plugin validate <dir>`.
- Skill changes in a plugin loaded from a local marketplace path apply at the next session or
  `/reload-plugins`; hooks need `/reload-plugins`.
